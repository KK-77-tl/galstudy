1. 产品定位

GalStudy 是面向所有学科学生的 AI 剧情学习平台。用户登录后上传自己的 PDF、PPTX、Word，系统解析、提取并允许校对知识点，AI 生成日式视觉小说主线与分支；用户边看剧情边答题，也可以随时和学习角色自由聊天，保存存档与错题。用户还可以付费上传参考图片，生成自己的专属 AI 陪学角色包。

两个赛事的侧重点：

支付宝智能体涌现奖：真实学习需求、智能体陪伴、剧情交互与可用体验；首轮预计12月初投稿。

PAYATHON 2026 / Vibe Pay：AI 应用接入支付并完成真实的“使用—付款—交付”闭环，报名约12月1日截止、作品约12月9日截止（以官网为准）。真实支付资质未获批时，不可把演示交易标成真实交易。

3. 完整核心使用流程

注册/登录；创建学习项目，上传 PDF/PPTX/DOCX。

后台分批提取文字、标题、来源文件及页码/幻灯片编号，扫描件使用可选 OCR；失败时报告原因。

AI 提炼定义、概念、易错点、习题，并保留原文片段与出处；用户必须能编辑/删除/补充，然后确认。

按确认后的知识点生成结构化故事：章节、人物、对话、选择分支、题目、正确答案、解析、结局与来源映射。

玩家用 Galgame 对话框与角色互动，选择分支并答题；错误自动记录错题本；剧情存档长期保存。

玩家可暂停剧情与当前角色自由聊天。聊天优先利用本课程的已确认知识点；没有资料依据时明确说明。

网页其他位置可呼出同一角色的悬浮陪学组件，收起/展开，不遮挡手机与电脑的主要操作。

重点：不能用一个普通聊天框冒充 Galgame；必须有可运行的节点、选择、不同分支和至少一个可达结局。答题评分和剧情状态由应用逻辑控制，不能完全交给模型随意改分。

4. 付费角色工坊

输入：用户上传本人有权使用的一张/多张角色参考图片，填写角色名字、人设、称呼、外观偏好。
首版预计：主立绘1张、约6个表情、约3个动作/姿态，可由配置调整；保持角色身份/脸部特征尽可能一致。
输出：专属角色包绑定用户账号，可在故事内和网页悬浮模式中使用；后续可扩充动态角色。

支付与生成状态：
选择角色包 → 创建待支付订单 → 支付宝完成付款 → 后端核实签名/金额/订单 → 发放一次性生成权益 → 生成任务排队 → ComfyUI → 结果审核与交付 → 存入个人角色库。

强制约束：

商品价格由服务端配置，不能相信前端传来的价格。

支付回调要验签、幂等、核对订单，失败/重复通知不会重复发权益。

没有真实支付资格时仅使用明显标示的 Mock/Sandbox，不进行真实扣款，也不谎称有真实订单。

没有 ComfyUI 环境时实现 MockCharacterGenerator 与 ComfyUICharacterGenerator 同一接口；Mock 使用授权演示图且明确标示为演示。

记录生成任务状态、可重试次数、超时、错误；失败时按约定恢复生成权益。

用户上传的真实人物照片必须有适当同意/授权；版权角色和敏感/不适合图像需有审核流程。保留私有图片的删除能力与最短必要存储策略。

暂不做声音克隆、跨软件的系统级桌宠、完整 ComfyUI 节点编辑器。

成本策略：

首期固定服务器≤100元/月为目标，不是承诺；大文件 OCR 并发高时可能需要升级。

云端模型、GPU、对象存储、流量、短信的计费不在这100元内，必须有用量/成本上限与告警。

不应在廉价主机上同时运行自托管大模型和 ComfyUI。ComfyUI 走按需 GPU 任务，生成后关停计算资源。

国内正式收费网站涉及适用的备案、资质、支付准入与平台规则，必须在正式上线前核查；开发完成不代表能够立即合法收费。

7. 开发阶段、交付物与验收

阶段-1：开源项目技术验证（阶段0之前，限定时间半天至一天）

目标：参考成熟项目的设计与实现方式，做出有证据的“集成 / 只借鉴 / 暂缓”决策，而不是把大型开源产品全部部署到 2核4GB 的入门服务器。

交付：docs/opensource-research.md、docs/architecture-decisions.md、docs/licenses.md 和一个可交互的小型视觉小说场景 PoC。参照第12节的项目清单与验证任务。

验收：

WebGAL 或 Pixi’VN 的技术路线已比较；能在浏览器演示人物立绘、背景、对话、两个选择、条件跳转、退出后续玩。

给出“第三方引擎直接集成”与“自主 JSON 剧情状态机 + UI”两种方案的集成成本、维护成本和许可证影响；确认一种作为阶段2方案。

证实 DOCX、PPTX 和文本型 PDF 的结构/出处提取；扫描件和复杂表格标明 OCR 策略及可测案例。

有向商业化迁移的开源许可证登记，明确禁止未经审查直接复制 AGPL 项目代码、演示素材、模型权重或工作流配置。

输出本机/服务器内存、CPU 与依赖风险，明确哪些组件在开发机器运行、哪些服务器运行、哪些按需外包 API/GPU。

此阶段不要求真实 AI Key、ComfyUI 或支付资质，不采购服务器。

阶段0：工程基座（最高优先级）

交付：前后端项目、数据库迁移、Docker Compose、.env.example、README、登录/访问控制、学习项目列表、Galgame 风格首页和基础角色素材。
验收：

本地一键启动，无白屏；健康检查通过。

用户未登录不可进入课程/资料/订单等私有页。

未填写 API Key 能启动并明显显示 Demo 模式。

不覆盖现有项目文件、不包含真实秘密配置。

阶段1：资料→可编辑知识点（P0）

交付：PDF/PPTX/DOCX 上传，异步解析，来源定位，知识点生成草稿、人工确认与错误提示，OCR 接口。
验收：

三种格式分别用一个原创样本跑通；页面能看提取结果和源页码/幻灯片。

人工修改知识点后可保存；错误格式/空文件/扫描无法识别时有明确反馈。

账号 A 不能读取账号 B 的文件或知识点。

阶段2：真正可玩的 Galgame（P0）

交付：结构化故事图、预生成章节、立绘/场景/对话框、分支选项、知识题、错题、存档和续玩。
验收：

一门演示课程至少有2个章节、多个有效选择、不同分支与可达结局。

题目答案、解析和来源可见，答错记录进错题本。

刷新、退出再登录能够从存档续玩。

剧情状态在代码里可预测、可回归测试。

阶段3：AI 陪学角色（P1）

交付：至少3个预设角色、人设配置、课程知识检索、流式自由聊天、网页悬浮角色、对话记忆。
验收：

不同角色说话风格可区分；同课程内容能回答和引用来源；未知时提示不确定。

悬浮层可拖动/收起，不挡住手机端主要按钮；各用户聊天完全隔离。

模型超时/余额不足有明确错误和降级策略。

阶段4：角色工坊+付费模拟闭环（P1）

交付：上传参考图、自定义、角色任务状态、资产库、ComfyUI接口、订单/权益/沙箱支付。
验收：

未付款没有生成权益；支付失败不放行；重复通知不重复发权益。

生成任务失败可以按规则重试或恢复权益；Mock 角色图片明确标示演示。

生成后可以在 Galgame 和悬浮陪学中选择该角色。

阶段5：公开演示与参赛准备（P1）

交付：在具备资源与授权后发布 HTTPS 演示站、1—3分钟评委演示脚本、测试清单、已知限制、提交材料草稿。
验收：

新用户能完整走完登录→上传→知识点→剧情→答题→错题→聊天→存档。

若是 Mock 生图/支付，演示和文案如实标注，没有虚假的真实收入。

PC 和手机主流浏览器可用；至少执行一次 Playwright 全流程测试。

阶段6：真实 ComfyUI + 真实支付宝支付（条件满足后）

交付：GPU 生图任务、稳定角色包、支付宝 Vibe Pay 正式接入、权益交付与退款/失败补偿机制。
验收：

使用有权处理的素材，真实合规订单支付后才发权益；生成成功入库，失败有补偿。

支付签名、金额、通知幂等、订单状态和用户权限经真实集成测试。

未具备法定/平台条件前不正式运营收费。

12.1 推荐的“借鉴—自研”边界

应用前端自主开发：保留 Next.js 课程空间、知识点校对、账户、聊天悬浮角色、付费角色工坊。不要将大型 SillyTavern/AnythingLLM 产品直接塞入前端。

剧情采用可验证状态机：生成端只允许输出预定义 story graph（章节、节点、对话、背景、角色、表情、分支、题目、来源引用）；运行端由代码管理变量、选择、评分与结局。WebGAL/inkjs 是否采用取决于 PoC 的插件化能力与存档一致性。

资料解析采用两级策略：普通 PDF、DOCX、PPTX 优先轻量 Python 解析；扫描件、复杂版面可由 Docling/OCR worker 异步处理。未安装 OCR/模型时真实提示“扫描件解析尚不可用”，不能假装成功。

检索由系统自己实现与隔离：以课程和账号为硬边界；每条事实能追溯文件页码或幻灯片。可参考 AnythingLLM 的资料对话流程，避免早期自托管整套多容器 RAG 平台。

AI 角色采用自己的数据模型：人设档案、课程上下文、对话记忆与调用限额保存在 GalStudy 中；参考 SillyTavern 的角色交互方式，但独立编码。

图像生成与购买相互解耦：先保证订单→权益→任务→角色包的业务状态机在 Mock 下正确，再配置独立 ComfyUI 服务。ComfyUI 典型接口包括 POST /prompt、GET /history/{prompt_id}、GET /view、WebSocket /ws；所有请求经 GalStudy 后端代理，GPU URL/用户图像不直接暴露前端。

12.2 开源许可证与美术合规底线

MIT：通常允许商业使用和修改，但应保留必要的版权与许可声明；字体、示例数据、模型权重、图片依各自许可证单独核查。

MPL-2.0：存在文件级源码披露、许可证与通知要求；直接修改/分发 WebGAL 时需评估相应义务。商用许可不等于可去除相关许可证要求。

AGPL-3.0：对向网络用户提供被修改程序的交互服务有源码提供义务；只借鉴公开的通用设计思想，不直接复制代码最省风险。

GPL-3.0：与 ComfyUI 通过 API 通信本身不等于直接复制或合并程序；发行/修改其代码时另外核查义务。具体结构及部署应在正式商用前审查。

任何开源项目的 UI 截图、默认立绘、背景、模型 checkpoint、LoRA、用户上传的真人/动漫角色图片都不能仅凭“项目开源”假定可商业使用。

12.3 Codex 必须完成的实验

实验A：剧情引擎选型（优先）

编写一小段原创两场景剧情：角色 A 与 B 不同表情、背景切换、两个分支、一个答题节点与一个可达结局。

路线一：以 WebGAL 官方例子为基础，验证 React/Next.js 中能否独立装载/卸载、外部传入动态剧情、接收答题事件以及持久化进度。

路线二：如果路线一不稳定或成本过高，用轻量 StoryPlayer + JSON Schema/Zod + Zustand（可选）自建状态机，完成相同演示。

交付路线比较表（交互质量、开发成本、动态 AI 剧情、内存/包体积、许可证、测试性），以比赛交付期为约束选定一种方案。

实验B：文档解析（优先）

以原创 PDF/PPTX/DOCX 样本验证标题、页码、段落/幻灯片编号、表格、中文英文混排；失败样本给错误原因。

记录普通解析器与 Docling 的 CPU 峰值、内存峰值、速度；若本机不能安装模型，则记录不可测原因和下一步测试方式，不捏造基准数据。

测试用户 A、B 的上传文件与知识点不能交叉检索。

实验C：角色 + 复习（可后置）

参考 SillyTavern 的人设/角色卡概念，设计 character profile、聊天历史摘要和课程知识引用的独立 Schema。

错题至少有“今天待复习”列表；若接入 ts-fsrs，锁定与 Node 版本兼容的发行版并写单测。

实验D：ComfyUI 连接（先 mock，真实接入后置）

实现 ImageGenerator 接口与 Mock/ComfyUI 两个适配器；验证任务排队、进度轮询、超时/失败重试、私有存储与一次性权益。

保存工作流配置模板并白名单允许修改的节点输入，不接受客户端任意工作流 JSON/任意服务 URL，防止滥用和 SSRF。

12.4 可直接发给 Codex 的新增首条指令（优先于阶段0）

GalStudy 第一次开发前请先执行 PRD v1.1 的“阶段-1：开源项目技术验证”。

请研究以下官方仓库及其 README、许可证、相关接口：
- OpenWebGAL/WebGAL：网页 Galgame 演出、动态剧情和存档集成；
- docling-project/docling：PDF/PPTX/DOCX 解析、复杂 PDF/OCR 和计算资源；
- Mintplex-Labs/anything-llm：按用户课程隔离的 RAG、来源引用；
- SillyTavern/SillyTavern：角色卡、人格、聊天记忆及视觉小说模式，只借鉴设计；
- Comfy-Org/ComfyUI：工作流提交、任务状态、输出文件的 API；
- 可选：inkle/ink、y-lohse/inkjs、open-spaced-repetition/ts-fsrs。

先检查现有仓库，绝不覆盖用户已有修改。不要直接克隆多个大仓库作为项目依赖，也不要复制 AGPL/来源不明的代码、立绘、模板和模型。请做最小可运行的 Galgame PoC，证明对话、背景、立绘、分支、答题和存档能连接到业务逻辑。比较 WebGAL 集成与独立 JSON 状态机；按动态故事扩展性、测试难度、许可证义务、交付工期选择。

输出 docs/opensource-research.md（每个项目的版本/Star/链接/许可证/结论）、docs/architecture-decisions.md、docs/licenses.md。未能实际测试的指标标记“未测试”，不要臆测。确认技术方案后进入阶段0，实施完整 GalStudy MVP。

主要参考：WebGAL 官方仓库、SillyTavern 官方仓库、Docling 官方仓库、AnythingLLM 官方仓库、ComfyUI 官方仓库和官方 ComfyUI Server Routes 文档（https://github.com/Comfy-Org/docs/blob/main/development/comfyui-server/comms_routes.mdx）。
